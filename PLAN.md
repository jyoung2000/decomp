# Reverse-engineering platform (R-series) — planned 2026-10-10

Goal in plain words: make Rebuild Studio a reverse-engineering tool that stands on its own without AI, gets better with a local model,
and better again with a cloud model — usable from its own window, from the command line, and from any AI client over MCP, the way an
agent would use Ghidra or Cutter. "Best" is never claimed by assertion: R0 defines the measurements and every later milestone moves one.

Facts this plan is built on (survey 2026-10-10; see `controller/rebuild_controller/mcp/server.py`, `backends/rizin_worker.py`, `providers/`):
- MCP today: 22 pipeline tools, stdio, standalone (`rebuild-mcp`), installers for Claude Code/Codex/Gemini/Hermes. RE primitives: 12 of 18 missing
  (disassemble range, xrefs, symbols, rename, retype, comment, patch, byte search, call graph, segments, struct types, ad-hoc open).
- No-AI native path: rizin 0.9.1 + rz-ghidra; the pipeline runs 6 of 12 backend ops and decompiles the first 200 functions in `aflj` order; no
  signatures/FLIRT, PDB, demangling policy, packer/entropy/overlay checks; Ghidra 12.1.4 headless is wired but has never executed.
- Cloud AI: OpenAI/Anthropic/Gemini/OpenRouter adapters + Connections UI (API key, DPAPI storage, probe) exist; 0 live calls ever (no keys).
- Local AI: proven end to end (detect → ladder → 6 attempts → verifier). On an RTX 4070 12 GB, qwen2.5:14b / deepseek-coder-v2:16b /
  gemma4:12b produced Rust that never compiled for the .NET fixture (evidence run 8). The loop is sound; the models are the limit.
